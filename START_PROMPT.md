Привет. Это проект VK Mini App — агрегатор стока кроссовок для реселлеров.

Сначала прочитай `CLAUDE.md` и файлы в `docs/` (STATUS.md, DECISIONS.md, ARCHITECTURE.md, TZ.md). Там вся суть, стек, правила и текущий статус. Всегда сверяйся с ними и держи их в актуальном состоянии.

Сейчас мне нужно ТОЛЬКО одно: инициализировать скелет проекта. Не пиши всю логику сразу. Конкретно:

1. Создай монорепо-структуру: папки `frontend/` (Vite + React + TypeScript) и `backend/` (Fastify + TypeScript) и `prisma/` (схема БД).
2. Подними минимально рабочий каркас: фронтенд показывает пустую страницу «СтокПоиск», бэкенд отдаёт один тестовый эндпоинт `/health`, они связаны.
3. В `prisma/schema.prisma` опиши сущности из `docs/ARCHITECTURE.md` (Seller, Brand, Model, Listing) для PostgreSQL. Миграции пока не запускай — просто схему.
4. Не подключай пока VKUI и vk-bridge — сначала обычное веб-приложение, обёртку в ВК сделаем позже.

После выполнения ОБЯЗАТЕЛЬНО:
- Обнови карту файлов в `CLAUDE.md` (какой файл за что отвечает).
- Обнови `docs/STATUS.md` (отметь сделанное, что дальше).
- Если принял важное техническое решение — добавь строку в `docs/DECISIONS.md`.

Объясняй коротко, что делаешь. Меняй минимально необходимое. Если что-то неоднозначно — спроси, не угадывай.

## Как работать дальше (твой ритуал на каждую сессию)

В начале новой задачи пиши примерно так:

> «Свериться с CLAUDE.md и docs/STATUS.md. Затем сделай [задача]. По карте файлов найди нужный файл, не читай весь проект. После — обнови STATUS.md и карту.»

Это держит Claude в рамках, экономит токены и не даёт ему забывать контекст.

## Мелкие правила, которые экономят токены

- Проси трогать конкретные файлы: «правь только `backend/src/search.ts`», когда знаешь, где задача.
- Большие задачи дроби на маленькие — короче контекст, точнее результат.
- Раз в несколько сессий проси: «проверь, что CLAUDE.md и STATUS.md соответствуют реальному коду».
- Не начинай новую крупную фичу, не обновив STATUS.md по текущей.
